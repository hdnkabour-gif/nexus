# Knowledge Center V3 — persistence and release checkpoint
Extends F26/F27/F42 and coordination issue #5, on V2 main 080be1f.
- Additive tables in the NEXUS database only; migration under existing transaction/advisory lock seeds the approved redacted index. Same identity/path/revision with changed payload is rejected. Different revisions preserved. Older records cannot silently become current; same-day ambiguous revisions excluded and counted. No destructive migration or source-app database access.
- Protected page reads database snapshot; explicitly labeled static fallback on unavailable storage. Task observations are allowlisted public GitHub metadata, not model execution receipts. The command `npm run knowledge:sync` stores changed observations, skips repeats and older arrivals, writes job receipt and exposes a failure/unknown exit code. No scheduler/service configuration is changed in this PR. Existing page-visit fetch remains separate; no claim of live private ingestion. 
- Setup after independent review: prove isolated migration/rollback and offsite recovery, authorize the NEXUS release separately, run the migration and verify count, then configure a dedicated bounded hourly command on approved NEXUS service. Verify receipts, rate limits and missed cycles; no unapproved production data writes. Use the existing private knowledge source review workflow; never import raw conversations, employer or customer records into public GitHub.

Requires dedicated server-side API credentials and explicit models/budgets, bounded redacted evidence, no automatic external calls or coding/merge/deploy permissions. ChatGPT/Astra session and Claude Code subscription are not API credentials. Model run receipts need actual provider/agent proof. No paid inference in V3.
