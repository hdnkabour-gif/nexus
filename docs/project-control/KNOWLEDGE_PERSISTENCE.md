## V3 review follow-up (#31): GitHub budget, append-only enforcement, ambiguity
- **Shared GitHub budget.** The console page and `knowledge:sync` reserve their reads from one hourly budget stored in `nexus_github_budget`: 50 requests per window, below GitHub's anonymous 60/h/IP. A batch that does not fit makes no request, and its tasks are `UNKNOWN` with reason `budget`. If GitHub returns `x-ratelimit-remaining: 0`, the window closes for every process. Without a database the budget is per process only.
- **Append-only in the database.** Triggers refuse UPDATE, DELETE and TRUNCATE on `nexus_task_observation_history` and `nexus_knowledge_revisions`. A table owner can still drop triggers, so the runtime role must not own these tables. Check this with the runtime role's URL: `node scripts/check-db-privileges.mjs` (read-only; exit 1 if the role is superuser, has BYPASSRLS, owns a history table, still has UPDATE/DELETE/TRUNCATE, or the triggers are missing).
- **Same provider timestamp.** Observations with the same `source_updated_at` but different state or head are kept and flagged `ambiguous` at read time. They are never ordered by arrival.
